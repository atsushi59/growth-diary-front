# 変更解説: 認証画面の実装＋API接続（フェーズ1 / ダミーモード）

Redmine #22 のフェーズ1。「フォーム → API → 画面遷移」というフロント・バック接続の“型”を、Cognito の複雑さ抜き（ダミーモード）で完成させた変更。

## 全体像

ログイン・サインアップ画面を実装し、submit したら認証必須の `GET /children` を叩いて 200 ならこどもページへ遷移する、という接続フローを作った。UI は cva ベースの Button / Input、API は `src/lib/api.ts` に集約。

## 詳細解説

### 1. src/vite-env.d.ts — 環境変数の型

```ts
interface ImportMetaEnv {
  readonly VITE_API_BASE_URL: string
}
```

Vite では `import.meta.env.VITE_xxx` で環境変数を参照するが、デフォルトでは型が付かない。この宣言で `import.meta.env.VITE_API_BASE_URL` を型安全に扱えるようにしている。

**ポイント（.env の VITE_ 接頭辞）**: Vite は `VITE_` で始まる変数だけをフロントのバンドルに露出する。秘密情報を誤って埋め込まないための仕組み。値は `.env` に書き、本体はコミットしない（`.gitignore` 済み）。代わりに `.env.example` でキーだけ共有する。

### 2. src/lib/api.ts — API クライアント（fetch 層）

すべての API 呼び出しをここに集約し、ベースURL付与・JSONヘッダ・トークン付与・エラー処理を一元化している。

```ts
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL
if (!API_BASE_URL) {
  throw new Error('VITE_API_BASE_URL が設定されていません。.env に設定してください。')
}
```

未設定だと `fetch('undefined/children')` になり全リクエストが静かに失敗するため、起動時に落として早期に気づけるようにしている（レビュー指摘の対応）。

```ts
if (init.body != null) {
  headers.set('Content-Type', 'application/json')
}
```

**ポイント（CORS プリフライト回避）**: ボディの無い GET に `Content-Type: application/json` を付けると、ブラウザが「単純リクエスト」とみなさず事前確認（プリフライト OPTIONS）を送る。不要なので、ボディがある時だけ付けるようにしている。

```ts
if (token) headers.set('Authorization', `Bearer ${token}`)
```

トークンが localStorage にあれば `Authorization: Bearer` を付ける。フェーズ1（ダミー）ではトークン無しでも 200 が返るので未使用だが、フェーズ2で Cognito のアクセストークンを載せる土台になる。非2xx は `throw` して呼び出し側の `catch` に流す。

### 3. src/components/ui/Button.tsx — cva ベースのボタン

cva（class-variance-authority）は「propsの組み合わせ → Tailwind クラス文字列」を宣言的に定義するライブラリ。

```ts
const buttonVariants = cva(BASE, {
  variants: { variant: {...}, tone: {...}, size: {...}, isSquare: {...} },
  compoundVariants: [
    { variant: 'primary', tone: 'solid', class: 'bg-primary text-primary-foreground ...' },
    ...
  ],
  defaultVariants: { variant: 'primary', tone: 'solid', size: 'medium', isSquare: false },
})
```

- **base（第1引数）**: どの組み合わせでも共通のクラス（角丸・フォーカスリング・disabled スタイル等）。
- **variants**: 軸ごとの選択肢。`size: { small, medium, large }` のように軸内で排他。
- **compoundVariants**: 「`variant=primary` かつ `tone=solid` のときだけ」という**複数軸の組み合わせ**に当てるクラス。色は variant と tone の掛け合わせで決まるためここで指定している。
- **defaultVariants**: props 未指定時の既定値。

色はすべてカラーシステムの役割名クラス（`bg-primary` 等）のみ。`buttonVariants({ ..., class: className })` で呼び出し側の追加クラスもマージする。

### 4. src/components/ui/Input.tsx — 制御コンポーネントの Input

```tsx
type InputProps = Omit<InputHTMLAttributes<...>, 'value' | 'onChange'> &
  VariantProps<typeof inputVariants> & {
    value: string
    onChange: (event: React.ChangeEvent<HTMLInputElement>) => void
  }
```

**ポイント（bind:value → value + onChange）**: Svelte の `bind:value` は双方向バインディングで input の値と変数が自動同期する。React にこれは無く、「値を props で渡す（`value`）」「変更を関数で受け取る（`onChange`）」を自前で繋ぐ**制御コンポーネント**で代替する。`value` と `onChange` を必須にして繋ぎ忘れを型で防いでいる。`isError` で枠線色を切り替え、エラー時は `aria-invalid` を付与（a11y）。

### 5. src/components/AuthForm.tsx — 認証フォーム本体

`mode: 'login' | 'signup'` で表示を切り替える共通フォーム。テキストや遷移先は `MODE_CONFIG` にデータとして分離している。

#### 入力状態とバリデーション

```ts
const isPasswordMismatch = isSignup && confirmPassword.length > 0 && password !== confirmPassword
const canSubmit = email.length > 0 && password.length > 0 &&
  (!isSignup || (confirmPassword.length > 0 && !isPasswordMismatch)) && !isSubmitting
```

signup のときだけ確認用パスワードを表示し、一致チェックはフロントで行う。不一致なら `isError` 表示＋submit 無効。

#### 接続ロジック（なぜ GET /children か）

```ts
await apiRequest('/children')
navigate('/children')
```

**ポイント**: バックには login/signup API が無い（認証は aws-jwt-verify によるトークン検証方式）。そこでフロントは「**認証必須の `GET /children` を叩いて 200 が返るか**」でログイン成否を判定する。ダミーモードでは検証が素通しなので、ここでの主眼はパスワードの実検証ではなく「接続の型」を作ること。

#### 二重送信ガード（レビュー指摘対応）

```ts
const isSubmittingRef = useRef(false)
if (!canSubmit || isSubmittingRef.current) return
isSubmittingRef.current = true
```

`event.preventDefault()` は「フォーム送信時のページ全体リロード」を止めるだけで、二重送信は防げない。state（`isSubmitting`）は反映が次レンダーまで遅れるため、Enter 連打などで二度目がすり抜け得る。**同期的にその場で更新される `useRef`** で再入を弾いている。フェーズ2で本物のサインアップに差し替えたときの二重登録防止になる。

### 6. src/pages/Login.tsx / Signup.tsx

各ページは `<AuthForm mode="login" />` / `<AuthForm mode="signup" />` を呼ぶだけ。骨組み段階の `<h1>` から差し替えた。

## フェーズ2（Cognito 差し替え）で残る/変わる部分

- **そのまま残る**: UI（Button/Input/AuthForm のレイアウト）、`api.ts` の fetch 層、画面遷移。
- **差し替わる**: `AuthForm` の submit を、ダミーの `GET /children` 疑似ログインから Cognito の本物サインアップ/ログインへ。取得したアクセストークンを `api.ts` の `Authorization` に載せ、バックは aws-jwt-verify で検証する（AUTH_MODE を本番モードへ）。

フェーズ2は #68（Cognito インフラ構築）完了が前提。
